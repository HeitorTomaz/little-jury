mock-jury, method 0.5.0 (2026-11-21)
0.5.0: clarity is no longer a score; the moderator runs a comprehension check on round 1 and reports pitch
problems apart from project problems. Strength questions in every round and a rule against criticism by
obligation. Round 3 with one user per model and a defender and a critic for each central rule. Contrarian
pack with an index; the contrarian may request up to six answers in full (two calls). Settled items skip the
debate; non-independent convergence and splits by model are recorded. One file per round. Persona texts
never promise tools; prompts flag a missing tool. Undefined audience: no averaging, audienceSplit section.
Optional checkpoints (after round 1, before the debate). Re-evaluation mode with comparison.md. The panel
never recommends running itself again.
0.4.0: quick wins. Experts propose, in round 2, the smallest change that would fix the most serious
problem they found; every debate reply adds the smallest change to a rule or decision that would solve the
point, and what is lost; a point with two or more different proposals gets a second turn where participants
support or oppose each one. Consolidation groups them by point in design-alternatives.md, and the report
has a "Quick wins" section (quickWins in report-data.json). Run scripts confined to the panel;
method/ and .claude/ write-protected during the run.
0.3.0: fully English skill; the skill talks to the user and writes every output in the user's language
(default English), recorded in config.md. No stops: a single question block in prepare, then an autonomous
isolated run via run_panel.py until the report. Report fonts shipped locally; 5,000-word scope threshold.
diversity.md guide based on pilot rounds 1-3; lessons from pilot rounds 4 and 5 still pending.
